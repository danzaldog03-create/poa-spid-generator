Configuración general

⚡ Autollenado de Ordenante
Estos datos se reutilizan automáticamente donde el layout del tipo seleccionado los requiera.
El folio de pago aumenta 1 por operación. Si tus últimas operaciones terminaron en 999, captura 1000. El rastreo también conserva su prefijo y cambia el consecutivo.
🔢 Continuidad de folios
Aquí defines los datos que deben continuar en el archivo actual. No se agrega ningún campo llamado “ciclo” al layout.
Ejemplo: si el último folio utilizado fue 999, captura 1000. La siguiente operación será 1001, luego 1002, etc. Las devoluciones también consumen folio de pago consecutivo.
📌 Campos fijos para la generación masiva
Marca un campo y captura su valor. El valor aparecerá inmediatamente en cada modelo y se escribirá en el TXT final.

📋 Layout completo de tipos de pago

Este catálogo es únicamente de referencia. El modelo de operación de la derecha usa exactamente estos campos y posiciones RP[n] para generar el archivo.

Encabezado del archivo (RE)

Se genera como 1~40036~0001~NNNN~. RE[4] es el total de operaciones que realmente se escribirán.
↩️ Devoluciones automáticas desde TXT recibido
Carga el TXT recibido, registra una o varias cuentas inválidas y la app identificará las operaciones que correspondan a esas cuentas. Para devolución normal utiliza tipo de pago 05 y causa 01 — Cuenta inexistente.
El archivo se procesa localmente en el navegador.
Las devoluciones generadas quedan como modelos separados. Puedes revisar el layout antes de generar el archivo final.

Operaciones modelo 0

Cada modelo puede representar muchas operaciones. El campo cantidad controla cuántas filas reales se generan.
🚀 Generación masiva por cuenta
Ejemplo: 10 modelos × 50 operaciones = 500 filas reales. El folio de pago y el rastreo avanzan automáticamente operación por operación.
Reglas: se usa ~ como separador. Nunca se utiliza ^. Los campos vacíos conservan su posición. RE[4] se calcula con las operaciones reales.
